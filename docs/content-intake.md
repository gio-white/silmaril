# Content intake

Everything the site needs from you. Nothing here blocks development — the site is built against
placeholder data and the real text swaps in section by section.

**Fill this in however is easiest.** Reply with it in a message, or edit the matching files in
`src/content/` directly. The field names below match the schemas.

## One thing worth knowing first

Placeholder content flatters a design, because invented bullets are shorter and more even than
real ones. The placeholders in this repo are deliberately awkward — long company names, bullets
that wrap to four lines — so the layout is stress-tested rather than tuned to fiction. Expect
small adjustments when your real text lands, and the more you provide early, the fewer of those
there are.

**The most useful thing to send first is your work history**, because the number of roles and the
length of the bullets materially shape the timeline design.

## 2. About

Three or four sentences. What problems you solve and at what scale — not adjectives.

Plus three or four headline metrics for the strip beneath it:

```yaml
metrics:
  - label: Years in the field
    value:
  - label: Largest daily volume
    value:
  - label:
    value:
```

## 3. Work history

One block per role, most recent first.

```yaml
company:
company_note:      # five words, only if the name isn't self-explanatory
                   # e.g. "B2B logistics, ~400 staff"
role:
start:             # YYYY-MM
end:               # YYYY-MM, or leave blank for current
location:          # optional
stack: []          # the tools you actually used here
highlights:
  - # 2-3 bullets. EACH ONE SHOULD CONTAIN A NUMBER —
    # volume, latency, cost, uptime, or people.
    # Bullets without numbers are the single biggest thing
    # that makes a CV forgettable.
```

## 4. Education

```yaml
institution:

field:
start:             # YYYY
end:               # YYYY
note:              # optional — thesis, honours, anything worth surfacing
```

## 5. Projects

Three to five. More than that and the good ones get diluted.

```yaml
title:
slug:              # url-safe, becomes /projects/<slug>
summary:           # one line
problem:           # what was actually wrong
approach:          # what you built
outcome:           # the result, with a number if at all possible
stack: []
links:
  repo:
  demo:
  writeup:
featured:          # true for the ones that should appear on the home page
period:            # optional, as it should read: "2026" or "2024 – 2025"
role:              # optional: "Solo", "Team of 4"
status:            # optional: live | archived | internal
tags: []           # optional topics, e.g. [Governance, Cost]
confidential:      # true for NDA work: links hidden, "details anonymised" note shown
kind:              # work | side (side projects can later get their own /lab page)
cover:             # optional image in src/assets/projects/, with alt text
  src:
  alt:
```

If a project deserves a full case study, also send the long-form text and any diagrams or
screenshots — that becomes the body of `/projects/<slug>`.

```yaml
  items: []
- group: Streaming
  items: []
- group: Cloud
  items: []

  items: []

  items: []

  items: []
```

No proficiency bars or star ratings. They are a cliché and they aren't honest.

## 7. Certifications

```yaml
issuer:
name:              # the exact official name
earned:            # YYYY-MM
expires:           # YYYY-MM, or blank if it doesn't
credential_url:
```

**One question that changes the design:** do you want issuer logos? That turns this from a text
list into an image grid, and whether you have one certification or nine changes it again. Tell me
the rough count.

## 8. Assets and settings

- **Domain name** — needed for absolute URLs in the Open Graph tags. Currently a placeholder in
  `astro.config.mjs`.
- **CV PDF** — goes in `public/cv.pdf`, linked from the hero and contact section.
- **Headshot** — optional. Say whether you want one.
- **OG preview text** — what the card says when you paste the link into Slack or LinkedIn.
  Defaults to your name plus the positioning line.
- **Favicon** — a monogram is generated by default unless you have something specific.
